🔄 Жизненный цикл приложения

Эту страницу можно приложить скрином к ДЗ. Ниже — все 6 этапов + цикл запроса.

А. Жизненный цикл приложения (хоста)

1
CreateBuilder

WebApplication.CreateBuilder: конфиг, логирование, DI-контейнер. Пустой шаблон.

2
ConfigureServices

builder.Services: AddHostedService, AddDirectoryBrowser…

3
Build

builder.Build() — финализация DI, создание WebApplication.

4
Configure Pipeline

app.Use… — сборка конвейера middleware. Порядок важен!

5
Endpoints

app.MapGet/MapPost — терминальные точки, формируют ответ.

6
Run / Stop

app.Run() → StartAsync; Ctrl+C → StopAsync. Kestrel слушает порт.

Б. Жизненный цикл запроса (наш конвейер)

Request (POST /submit, форма)
   │
   ▼
┌─────────────────────────┐
│ 1. RequestLoggingMiddleware │  лог входа → ... → лог выхода, заголовок X-Logged-By
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 2. RequestTimingMiddleware  │  Stopwatch, заголовок X-Response-Time-ms
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 3. FormValidationMiddleware │  ПРИВЯЗАН К ФОРМЕ:
│                         │  валидно? → Items + next → endpoint
│                         │  НЕ валидно? → 400 + short-circuit (endpoint НЕ вызывается)
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 4. LifecycleHeadersMiddleware│ заголовки X-Lifecycle-Stage, X-App
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 5. Endpoint POST /submit    │  формирует HTML-ответ (терминальный)
└────────────┬────────────┘
             ▼
        Response ──► обратно вверх по цепочке ──► браузер

В. Short-circuit (короткое замыкание)

Если FormValidationMiddleware находит ошибки — он не вызывает _next, а сам пишет ответ 400. Endpoint не выполняется. Это ключевое понятие жизненного цикла запроса.
